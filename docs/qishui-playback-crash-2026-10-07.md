# 汽水在线播放与原生崩溃修复

用户提供的 `halcyon-log-20261007-204528.txt` 来自更新修复包之前的 vivo
V2463A、Android 16，涉及歌曲“情浅如烟”。日志中的播放地址与签名不在此保存。

- 20:45:14.501 播放失败，原因是源地址从 HTTPS 跳转到 HTTP，被在线播放使用的
  WebDAV 认证客户端拒绝。限量读取这条转发链得到 HTTP 200、`audio/mp4` 和
  `ftyp` 文件头；取链成功并不证明解码或整曲播放成功。
- 20:45:14.942 后台读取音频属性时发生 SIGSEGV。原生栈位于
  `liblyrico_taglib.so`，经过 `Java_com_lonx_audiotag_TagLib_getAudioProperties`。
  JNI 入口及故障地址与修复前当前预编译库吻合。这一缺陷仍存在于上一修复包，
  并非仅凭旧日志推断新包回归。
- MP4 有 `ftyp` 但缺少完整 `moov` 时，TagLib 尚未创建标签对象。
  无效文件的兼容分支继续调用 `properties()`，会解引用空标签。

内容检测现在先确认标签对象存在，再检查无效文件是否仍有可读标签；保留原来的
标签兼容行为。已重编译并更新 arm64 原生预编译库。

LX、MusicFree 的网络媒体使用独立的播放器客户端，允许公开音频的转发链，
不借用私有音乐库的认证客户端。网易云队列交由插件解析后的子媒体源使用相同
路径，逻辑歌曲信息和队列身份保留。私有音乐库的传输规则和插件请求头的作用域
继续由各自的客户端处理。本地下载歌曲继续使用原来的本地文件路径。

验证记录位于 `app/build/outputs/qishui-crash-20261007/`：

- 在连接的 arm64 设备运行独立原生程序。旧代码对缺少 `moov` 的样本退出 139；
  新代码通过 7 个样本，包括截断 MP4、空文件、非音频内容、仅有标签的 MP3 和
  正常 WAV。测试程序和样本已从设备清理，没有安装应用。
- 复用现有单元测试验证公开插件媒体的转发、网易云插件传输标记、私有音乐库与
  本地文件保留原路径、插件请求头作用域和拒绝 URL 内嵌用户名密码。
- Release 验签、原生库一致性和源码快照结果见 `release-verification.json`。

实际新包的整曲在线播放仍需设备复测；上述网络检查只读取有限的文件头，没有
验证整曲解码，也不对其它音源返回的加密音轨作出可播放保证。
